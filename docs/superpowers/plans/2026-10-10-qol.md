# DubTV+ 1.1 implementation plan

**Goal:** Implement the user's approved QoL additions while preserving existing speed, quality and episode navigation.
**Architecture:** One installable userscript built by concatenating two dependency-free source modules. Player/UI in src/player.js; catalogue/library in src/library.js. Shared entry point calls createLibraryTools(panel), whose returned refresh function is called on DOM/route updates.
**Tech stack:** Browser DOM, CSS, localStorage, same-origin authenticated GET for existing lists only; Node for deterministic concatenation.
**Spec:** User request and attached screenshot in this chat, 2026-10-10.

## Requirements
- Theatre fills viewport width and height in normal document flow; page remains scrollable; contain video, no cropped content or gradient outside player; existing fullscreen remains separate.
- Reversible per-title Not interested with management UI; badges for native list statuses and hide completed in catalogue; no list/account writes.
- Collapsible description/comments/related sections with persisted choices; gradient toggle and normal player height setting.
- Real remaining time based on actual speed, additional shortcuts (episode, speed, jump time) ignoring editable controls, undo viewer seeks with timeout and source-change reset.
- All controls in small accessible DubTV+ dialog; no dependencies or privileged grants.

## Review focus
- Native React rerenders and SPA changes must not duplicate controls or retain global theatre styling.
- Storage failure and malformed values must not break the website.
- Failed list requests must show an honest retryable state; never hide based on unknown status.
- Keyboard actions must not intercept typing, modifiers or normal browser shortcuts.
- Undo seeks must not survive a different episode or trigger on resume/history restoration.
